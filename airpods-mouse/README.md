# AirPods Mouse 原型

验证 AirPods 能否控制 Mac 光标的 macOS 菜单栏应用，支持戴在头上，也支持握在手里或放在开盖的充电仓里举着转动。需要 macOS 14 及以上和 Xcode。

```bash
swift test
```

```bash
./scripts/build-app.sh
```

```bash
open build/AirPodsMouse.app
```

## 手持或举仓

1. 在“系统设置 > 蓝牙 > AirPods”里关闭“自动入耳检测”，否则离耳后没有运动数据。
2. 确认音频输出是 AirPods，把耳机握在手里或放进开盖的仓。
3. 在菜单里点“校准手持”，8 秒内把设备快速抬起再放下，听到提示音表示完成。
4. 打开“控制光标”，第一次需要授予辅助功能权限。

点击方式：

- 打开“手腕快翻点击”后，快速向左翻再翻回是左键，向右翻再翻回是右键。
- `⌃⌥⌘C` 左键，`⌃⌥⌘R` 右键。
- `⌃⌥⌘D` 按下左键开始拖拽，再按一次松开。

耳机在仓里的朝向不固定，换手或换握法后要重新校准。测完记得打开自动入耳检测。

## 验证佩戴模式

先在菜单里关闭“手持模式”。

1. 戴上 AirPods，连接到这台 Mac，允许运动权限，菜单栏应显示每秒收到的样本数。
2. 切换到其他应用继续转头，确认频率不掉。这是方案能否成立的关键。
3. 打开“控制光标”，按提示授予辅助功能权限，方向反了就用菜单里的反转选项。
4. 最后打开“点头点击”。它会真实点击光标下的内容，测试时先把光标放在安全的位置。

`⌃⌥⌘P` 可以随时开关头部控制，转到极限时先暂停、回正，再继续。耳机断开会自动关闭控制。

每次运行的数据写在 `~/Library/Logs/AirPodsMouse/`：`motion-*.csv` 是原始运动数据，`status-*.log` 每秒记录频率和当前前台应用。

打包脚本优先使用钥匙串里的 Apple Development 证书，这样重新构建后不用重新授予辅助功能权限。没有证书时退回临时签名，每次构建都要重新授权；设置 `SIGN_IDENTITY` 可以指定证书。

## 实测结论（2026-11-03，AirPods 5）

- 关闭自动入耳检测后，耳机握在手里或放在开盖的仓里，都能持续输出约 50 Hz 的运动数据，应用在后台也不断。
- 开着自动入耳检测时，摘下耳机后运动数据会停止。
- 充电仓本身没有可读取的传感器，也没有公开接口；仓正面的双击用于配对和重置，应用读不到。
- 举仓转动控制光标、手腕快翻点击都能触发，移动手感调整后用户确认跟手。
- 合盖实测：运动连接随即断开，数据中断约 17 秒直到重新连接，恢复后约 1 秒有数据，校准还在，但“控制光标”要重新打开。
- 离耳时连接后约 4 分钟数据会停（实测 3.5 到 4 分钟多）。一次仓外测试在连接 4 分 10 秒后变成 0 Hz，又过约 5 分钟才报告断开，因此不只是仓内充电造成的。
- 未验证：盖子虚掩能否继续输出、小目标点击精度、长时间误触率。偶尔出现连接着却没有数据的情况，原因不明。
